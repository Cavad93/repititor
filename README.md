# Repititor - Telegram бот для поиска скидок

## Описание проекта

Repititor это интеллектуальный Telegram бот, который помогает пользователям находить лучшие скидки, отслеживать цены на товары, получать актуальные промокоды и экономить деньги на покупках. Бот работает на базе Python с использованием современного асинхронного фреймворка aiogram версии три и PostgreSQL для хранения данных.

## Технический стек

Проект построен на следующих технологиях:

**Основные компоненты:**
- Python версии три точка одиннадцать - современная версия языка с поддержкой всех асинхронных возможностей
- aiogram версии три - асинхронный фреймворк для работы с Telegram Bot API
- PostgreSQL версии пятнадцать - надежная реляционная база данных для хранения пользовательских данных
- Redis версии семь - быстрое key-value хранилище для кэширования
- RabbitMQ - брокер сообщений для обработки асинхронных задач через Celery
- Docker и docker-compose - контейнеризация для простого развертывания

**Архитектура:**
Проект организован по модульной архитектуре, где каждая функциональная область вынесена в отдельный модуль. Такой подход делает код читаемым, легко тестируемым и масштабируемым.

## Установка и запуск

### Предварительные требования

Для работы бота на вашей системе должны быть установлены:

**Для Windows:**
- Docker Desktop для Windows (версия четыре точка ноль или выше)
- Python версии три точка одиннадцать или выше (если планируете разработку локально без Docker)
- Git для клонирования репозитория

**Для iOS (macOS):**
- Docker Desktop для Mac (версия четыре точка ноль или выше)
- Python версии три точка одиннадцать или выше
- Git (обычно предустановлен в macOS)

### Шаг 1: Клонирование репозитория

Откройте терминал (в Windows это может быть PowerShell или Command Prompt, в macOS это Terminal) и выполните команду для клонирования проекта:

```bash
git clone https://github.com/yourusername/repititor.git
cd repititor
```

Эта команда скопирует все файлы проекта на ваш компьютер в папку repititor и перейдет в эту директорию.

### Шаг 2: Создание файла окружения

Файл точка env содержит все секретные данные и конфигурационные параметры вашего бота. Эти данные не должны храниться в репозитории git, поэтому мы создаем их локально.

Скопируйте файл примера и откройте его для редактирования:

```bash
cp .env.example .env
```

В Windows используйте команду:
```bash
copy .env.example .env
```

Откройте файл точка env в любом текстовом редакторе и заполните необходимые значения:

**BOT_TOKEN** - это токен вашего Telegram бота. Чтобы получить его:
1. Найдите в Telegram бота @BotFather
2. Отправьте команду /newbot
3. Следуйте инструкциям для создания бота
4. Скопируйте токен который выдаст BotFather
5. Вставьте токен в файл точка env вместо your_bot_token_here

**POSTGRES_PASSWORD** - придумайте надежный пароль для базы данных PostgreSQL. Это может быть любая строка, например: MySecurePass2024

**REDIS_PASSWORD** - аналогично, придумайте пароль для Redis, например: RedisSecure2024

Остальные параметры можно оставить без изменений для начала работы.

### Шаг 3: Запуск через Docker

Docker позволяет запустить все компоненты системы (бота, базу данных, Redis, RabbitMQ) одной командой, изолированно от вашей операционной системы.

**Для первого запуска:**

Убедитесь что Docker Desktop запущен и работает. В Windows это можно проверить по значку Docker в системном трее. В macOS ищите значок кита в верхней панели меню.

Выполните команду для сборки и запуска всех контейнеров:

```bash
docker-compose up --build
```

Эта команда выполнит следующие действия:
1. Скачает необходимые базовые образы (PostgreSQL, Redis, RabbitMQ)
2. Соберет Docker образ вашего бота из Dockerfile
3. Создаст сеть для связи между контейнерами
4. Запустит все сервисы

При первом запуске это может занять несколько минут, так как Docker будет скачивать базовые образы.

Когда вы увидите в логах сообщение "Бот успешно запущен и готов к работе", это означает что бот работает и принимает сообщения. Теперь можете открыть Telegram, найти вашего бота по имени и отправить команду /start.

**Для остановки бота:**

Нажмите комбинацию клавиш Ctrl+C в терминале где запущен docker-compose. Все контейнеры корректно остановятся.

**Для повторного запуска:**

Если вы уже собирали образы ранее, можно запускать без флага build:

```bash
docker-compose up
```

**Для запуска в фоновом режиме:**

Если хотите чтобы бот работал в фоне и не занимал терминал:

```bash
docker-compose up -d
```

Флаг минус d означает detached режим. Бот будет работать в фоне.

Чтобы посмотреть логи работающего бота:

```bash
docker-compose logs -f bot
```

Флаг минус f означает follow и будет показывать логи в реальном времени.

### Шаг 4: Проверка работы

Откройте Telegram и найдите вашего бота по имени который вы указали при создании через BotFather. Отправьте команду /start. Если всё настроено правильно, бот ответит приветственным сообщением и покажет главное меню.

Вы также можете проверить что все сервисы запущены командой:

```bash
docker-compose ps
```

Она покажет статус всех контейнеров. Все они должны быть в состоянии Up.

### Локальная разработка без Docker

Если вы разработчик и хотите запускать бота локально для разработки и отладки без Docker:

**Шаг 1: Установите PostgreSQL локально**

В Windows скачайте установщик с официального сайта postgresql.org. В macOS можно использовать Homebrew:

```bash
brew install postgresql@15
brew services start postgresql@15
```

Создайте базу данных:

```bash
createdb repititor_db
```

**Шаг 2: Установите Redis локально**

В Windows можно использовать WSL или скачать сборку для Windows. В macOS через Homebrew:

```bash
brew install redis
brew services start redis
```

**Шаг 3: Установите RabbitMQ локально**

В macOS через Homebrew:

```bash
brew install rabbitmq
brew services start rabbitmq
```

**Шаг 4: Создайте виртуальное окружение Python**

Виртуальное окружение изолирует зависимости проекта от глобальных пакетов Python:

```bash
python -m venv venv
```

Активируйте окружение:

В Windows:
```bash
venv\Scripts\activate
```

В macOS/Linux:
```bash
source venv/bin/activate
```

**Шаг 5: Установите зависимости**

```bash
pip install -r requirements.txt
```

**Шаг 6: Обновите файл точка env**

Измените хосты в файле точка env на localhost:

```
POSTGRES_HOST=localhost
REDIS_HOST=localhost
RABBITMQ_HOST=localhost
```

**Шаг 7: Запустите бота**

```bash
python main.py
```

Бот запустится локально и вы увидите логи прямо в терминале.

## База данных

### Схема базы данных

Проект использует три основные таблицы:

**Таблица users** хранит информацию о пользователях Telegram. Каждая запись содержит уникальный Telegram ID пользователя, его имя и username из профиля, дату регистрации и последней активности, уникальный реферальный код для приглашения друзей, и ссылку на пользователя который его пригласил.

**Таблица subscriptions** управляет подписками. Здесь хранится тип подписки (пробная или оплаченная), даты начала и окончания, информация об использовании пробного периода, способ оплаты и настройки автопродления.

**Таблица user_preferences** содержит персональные настройки пользователя: выбранные категории товаров, любимые магазины, ценовой диапазон для фильтрации, частоту уведомлений и предпочитаемое время их получения.

### Миграции

При первом запуске через docker-compose база данных автоматически инициализируется и создаются все необходимые таблицы. Это происходит в функции init_db в файле database/connection.py.

Для production окружения рекомендуется использовать Alembic для управления миграциями базы данных. Это позволит версионировать изменения схемы и безопасно обновлять структуру БД.

## Логирование

Система логирования настроена для работы на трех уровнях:

**Консольные логи** выводятся в терминал с цветным форматированием для удобной разработки. Разные уровни важности (DEBUG, INFO, WARNING, ERROR) отображаются разными цветами.

**Файловые логи** сохраняются в директории logs в структурированном JSON формате. Это удобно для автоматической обработки и анализа. Файлы автоматически ротируются когда достигают размера десять мегабайт.

**Логи ошибок** выделены в отдельный файл errors.log для быстрого поиска проблем.

Для production окружения рекомендуется настроить отправку логов в ELK stack (Elasticsearch, Logstash, Kibana) для централизованного мониторинга и визуализации.
